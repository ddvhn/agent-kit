# Go data

How-to: `adding-go-modules` (Transactor, repositories, sqlc entry), `writing-go-migrations` (goose), `isolating-tenants-in-postgres` (SQL).

- `pgx/v5` with `pgxpool`, one pool per database role, sized against the database's connection limit.
- Every transaction goes through `internal/platform/db` (`InTx`, `InSnapshotTx`), which sets the scope with `set_config(…, true)` first and always rolls back on error. No network or provider call inside a transaction.
- One `infra/queries.sql` per module, generated by sqlc into `infra/db`; queries named `VerbNoun`, parameters by name, tenant filter explicit even under RLS, keyset pagination.
- Repositories implement domain ports over the generated queries, map rows to domain types (an invalid stored value is an error), turn `pgx.ErrNoRows` and constraint violations (by SQLSTATE and constraint name) into typed errors, never open transactions, never call each other.
- Racing updates use `SELECT … FOR UPDATE` or a conditional `UPDATE … WHERE status = $old`.
- Migrations are goose SQL files in `migrations/`, `-- +goose Up` only, embedded and run by the `migrate` subcommand as the migrator role; roles come from a bootstrap script.
